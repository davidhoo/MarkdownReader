# Markdown Reader v2.3.1 Functional Rollback Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 发布版本号高于 v2.3.0 的 v2.3.1，使已安装 v2.3.0 的用户通过现有自动更新回到 v2.2.10 的应用功能状态，同时保留 Git 历史、发布审计与用户数据。

**Architecture:** v2.3.0 已改为 draft，`/releases/latest` 当前指向公开的 v2.2.10；此状态在 v2.3.1 发布前必须保持。新 release 分支从当前 `origin/main` 建立，以 `git revert -m 1 e44317a0277624d166ba6360a07883de9aede61b` 反转 PR #15 的 merge 差异，再恢复 v2.3.0 的历史发行记录并写入 v2.3.1 元数据。v2.3.1 的应用源码必须与 v2.2.10 完全相同，而版本号更高会被既有 `UpdateService.isNewer` 识别为可更新。

**Tech Stack:** Git merge-revert, Swift 6.2+, SwiftUI, AppKit, WebKit, XCTest, Swift Package Manager, GitHub CLI, GitHub Releases, macOS arm64 ad-hoc signing, Jekyll, Homebrew Cask.

**Step 4: 验证 GitHub latest、资产和更新比较**

```bash
gh release view v2.3.1 --repo davidhoo/MarkdownReader \
  --json tagName,isDraft,isPrerelease,targetCommitish,assets,url
gh api repos/davidhoo/MarkdownReader/releases/latest \
  --jq '{tag_name,draft,prerelease,html_url,assets:[.assets[]|{name,size,digest}]}'
gh release view v2.3.0 --repo davidhoo/MarkdownReader --json tagName,isDraft
```

验收：v2.3.1 是公开的 latest，含非空 DMG/ZIP；v2.3.0 仍是 draft。应用内比较 `2.3.1 > 2.3.0`，因此现有 v2.3.0 用户收到更新；2.2.10 用户同样会收到 v2.3.1。下载资产后再执行：

```bash
gh release download v2.3.1 --repo davidhoo/MarkdownReader \
  --pattern 'MarkdownReader.dmg' --pattern 'MarkdownReader.zip' \
  --dir /tmp/markdownreader-v2.3.1-verify
plutil -p /tmp/markdownreader-v2.3.1-verify/MarkdownReader.dmg
shasum -a 256 /tmp/markdownreader-v2.3.1-verify/MarkdownReader.dmg \
  /tmp/markdownreader-v2.3.1-verify/MarkdownReader.zip
```

`plutil` 不能直接读取 DMG 内的 Info.plist；先挂载 DMG 后验证实际 app：

```bash
hdiutil attach /tmp/markdownreader-v2.3.1-verify/MarkdownReader.dmg
plutil -p /Volumes/Markdown\ Reader/MarkdownReader.app/Contents/Info.plist
file /Volumes/Markdown\ Reader/MarkdownReader.app/Contents/MacOS/MarkdownReader
codesign --verify --deep --strict /Volumes/Markdown\ Reader/MarkdownReader.app
hdiutil detach /Volumes/Markdown\ Reader
```

验收：两个 bundle 版本均为 2.3.1、二进制为 arm64、签名验证通过。

## 三、完成标准

1. v2.3.0 仍为 draft；直到 v2.3.1 公开前 `/releases/latest` 为 v2.2.10，之后为 v2.3.1。
2. v2.3.1 的 `Sources/MarkdownReader` 与 `Sources/MarkdownReaderKit` 相比 v2.2.10 无任何差异；未撤销 v2.2.10 之后的公开文档更新。
3. revert commit 和元数据 commit 分离；v2.3.0 历史在 changelog/Release Notes 中保留并明确标记撤回。
4. 调试/发布构建、完整 `swift test`、Jekyll build、DMG 内版本/架构/签名与 GitHub Release API 验证全部通过。
5. v2.3.1 为公开 latest 且有可用 DMG/ZIP；已安装 v2.3.0 的用户会把 v2.3.1 视为新版本并更新到 v2.2.10 的功能状态。

## 四、失败处理与回滚

- Task 1–3 任一验证失败：停止在 release 分支，不推送 tag、不创建 v2.3.1 Release，v2.3.0 继续保持 draft，latest 继续为 v2.2.10。
- merge-revert 冲突无法严格恢复到 v2.2.10 源码：执行 `git revert --abort`，不以手动删代码替代；重新审查父提交和差异后再行动。
- tag 推送后、资产公开前失败：保留 v2.3.1 draft 并停止；删除 tag/Release/资产是破坏性操作，必须单独获得明确授权。
- v2.3.1 发布后发现问题：保持 v2.3.0 draft，不重写任何旧 tag 或资产；以新的更高版本修复，或先请求授权后变更 v2.3.1 的公开状态。
- 回退不删除 `defaultSplitPreview` 等遗留 UserDefaults key。v2.2.10 功能状态会忽略未知 key，用户现有文档、设置、编辑缓存和 Quick Look 配置不做迁移或清理。

## 不包含

- 不定位或修复 v2.3.0 的具体 bug；本任务只实现稳定功能回退，根因分析另行进行。
- 不让已安装用户的 bundle 版本号降为 2.2.10；用户会升级到 2.3.1，但功能回到 v2.2.10。
- 不 reset/force-push `main`，不删除或移动 v2.2.10/v2.3.0 tag，不删除 v2.3.0 assets，不修改历史发布的校验和。
- 不修改 `UpdateService.swift`、`UpdateViewModel.swift`、`build-app.sh`、`release-local.sh`、`package.sh`、Release workflow、签名/公证策略或用户更新协议。
- 不改产品功能、README、Pages 功能内容、Quick Look/PDF/多窗口架构；Pages 仅同步维护版本号。
