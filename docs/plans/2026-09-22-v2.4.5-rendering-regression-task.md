# v2.4.5 渲染样式与模式切换回归修复任务

日期：2026-09-22

状态：调查完成，待实现；本次仅新增任务文档。

优先级：P0，影响正常阅读与编辑后返回渲染。

代码基线：`main` / `v2.4.5`，`3a18782b6931f016e7069d8fc054392e1b09fe00`。

## 1. 结论与目标

**已确认的主因是打包后的资源目录与运行时查找规则不一致。** v2.4.5 安装包内 CSS、JavaScript 文件都存在，内容也与当前源码一致，但 `MarkdownURLSchemeHandler` 找不到它们，返回 404。缺失 CSS 导致字体、间距、表格等回退到浏览器默认样式；缺失 `markdown-reader.js` 导致 `MR` 对象不存在，内容替换和模式切换需要的滚动回执失败。

模式切换还有一个故障处理缺口：页面加载结束被当作渲染完成，而资源失败、JavaScript 异常未形成可恢复的失败状态。Raw → Rendered 过渡等待渲染完成和滚动回执，回执缺失时会一直保留 Raw 画面；此时 `displayMode` 已变成 Rendered，Raw 还被禁止交互，符合“切回渲染失败”的现象。

本任务目标：恢复发布包中渲染资源的可靠加载，使“渲染 → 编辑 → 渲染”首次切换成功，并建立发布包资源验收及失败退出机制。

### 用户确认的具体表现

复现操作：**渲染模式 → 编辑模式 → 再切回渲染模式**。该操作不应以修改内容作为复现前提；不修改和修改内容两种情况均须验收。

用户补充确认：

- 模式按钮显示已经处于渲染模式。
- 内容区视觉上仍然显示编辑模式的 Markdown 源码。
- 内容区不能滚动、不能选择文本等，处于无法正常交互的状态。

这组症状与现有代码中的状态组合吻合：`displayMode == .rendered`、`renderedTransition.keepsRawVisible == true`。前者使按钮显示渲染模式，并关闭 Raw 的命中测试；后者继续显示 Raw 并隐藏 WebView。修复必须同时恢复按钮状态、实际内容和交互能力的一致性，不能仅更改按钮文案或强行隐藏遮罩。

### 2.2 资源路径不匹配

安装应用与 ZIP 内的实际路径为：

```text
MarkdownReader.app/Contents/Resources/
  MarkdownReader_MarkdownReader.bundle/
    Contents/Resources/Resources/
      css/markdown.css
      css/scroll.css
      js/markdown-reader.js
      js/prism-core.min.js
```

但 `Sources/MarkdownReaderKit/Services/MarkdownURLSchemeHandler.swift:67–95` 的默认候选路径为：

```text
<main.resourceURL>/MarkdownReader_MarkdownReader.bundle/Resources/<path>
<main.resourceURL>/Resources/<path>
<main.resourceURL>/<path>
```

它没有通过内层 `Bundle.resourceURL` 解析 `.bundle`，因此漏掉 `Contents/Resources` 这一层。`Package.swift` 使用 `.copy("Resources")`，内层 bundle 的资源根目录之下还需要保留被复制的 `Resources/` 子目录。

旧构建缓存 `.build/arm64-apple-macosx/release/MarkdownReader_MarkdownReader.bundle` 是平铺结构，当前 `.build/out/Products/Release` 与安装包是带 `Contents` 的结构。`build-app.sh:48、85–100` 已改为从 SwiftPM 实际输出目录复制整个 bundle，但运行时仍假定旧结构。

`markdown.css`、`scroll.css`、`markdown-reader.js`、`prism-core.min.js` 的安装版内容均与源码逐字节一致。这排除了这四个文件丢失或旧脚本未更新的解释。

## 3. 修复约束

- 保持现有主题、字体栈和 Markdown 渲染行为；不要通过改字号、换字体或覆盖 CSS 来掩盖资源加载失败。
- 保持单个常驻 WebView、窗口隔离、源码锚点、latest-wins 世代校验、撤销及未保存内容语义。
- 支持平铺 bundle 与带 `Contents` 的 bundle；不要依赖开发机 `.build` 绝对路径、当前工作目录或旧缓存。
- 资源定位应覆盖主应用、预热、Quick Look 和 PDF 备用路径，避免各自再增加一套目录猜测。
- 保留本地图片、相对资源、Markdown 内链和显式 `resourceSearchPaths` 的既有用途。本任务不重写 URL 路由和文件访问策略。
- 失败不能伪装为成功，不能靠固定延时强制显示旧页面，也不能无限自动 reload。
- 用户提示通过 `L10n` 提供简中、繁中和英文；日志需区分资源缺失、运行时未就绪、JavaScript 执行失败及取消/过期请求。

### T2 — 为渲染失败提供明确出口（P1，本任务内完成）

建议文件：`WebViewMarkdownView.swift`、`WebViewRenderScheduler.swift`、`DetailView.swift`、`LocalizationService.swift` 及对应测试。

实施要求：

1. 区分“加载结束”和“渲染就绪”：首屏、整页加载以及 `.none` 完成路径不能只依据 `page.isLoading`。就绪检查至少确认必需 CSS 已生效，以及 `MR.replaceContent`、锚点采集/定位入口存在；具体检查信号需可测试。
2. 将当前渲染请求的资源/JS 失败传回窗口内状态。对有效请求，结束等待并恢复可编辑 Raw，模式按钮同步回到编辑模式，恢复滚动和文本选择；保留最新内容、dirty 状态、选择和 Undo，显示可理解的失败提示，允许用户再次尝试。
3. 对滚动等待设置有界的失败处理；超时只表示失败，不能当作成功回执。明确错误无需等到超时；不循环自动重载。
4. 失败与成功一样受当前文件、内容版本、世代及交接 ID 约束。快速切换或换文件后，旧请求的错误不得把新窗口状态切回 Raw。
5. 不改变“正文替换需显式 true、滚动需有效回执”的成功条件。资源恢复后再次切换必须能正常完成，不能残留失败快照或过渡状态。

完成标准：正常路径无新增可见等待；缺失 CSS、缺失 MR、JS throw、滚动回执未到达时均不会无限停留在不可编辑的 Raw 遮罩。

## 6. GUI 验收矩阵

使用同一份临时 Markdown 样本，包含中文、英文、H1/H2、粗体、链接、引用、列表、表格、行内代码、Swift 代码块及本地图片；另准备 Mermaid、KaTeX 样本。编辑临时副本，避免修改用户文档。

| 场景 | 通过条件 |
|---|---|
| 从打包应用首次打开普通文档 | 系统字体栈、正文间距、标题、表格边框、代码样式、主题均正确；核心资源成功加载 |

| 渲染 → 编辑，修改一句话后 → 渲染 | 最新渲染内容立即生效，按钮与内容一致，可滚动、可选择文本；不要求再次切换、刷新或重开文件 |
