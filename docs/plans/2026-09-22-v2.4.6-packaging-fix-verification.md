# v2.4.6 发布包混入旧程序：修复与验收记录

日期：2026-09-22。状态：本地修复并验收，尚未发布；未替换 `/Applications/MarkdownReader.app`。

## 原因

`build-app.sh` 的 `--target MarkdownReader --target MarkdownReaderQL` 实际只构建最后一个目标。主程序随后从历史 Release 输出目录复制，Quick Look 又从另一套旧 native 对象目录链接。于是包内版本号、资源已更新，运行的机器码仍是旧版本。

此前的独立验证器重新编译新 locator/handler 后读取包内资源，没有执行发布主程序，因此错误包也能通过。

## 修改

- 主程序使用 `--product MarkdownReader` 构建并链接，Quick Look 使用独立的 `--target MarkdownReaderQL` 命令。
- 每次打包使用新的 `--scratch-path`，结束后清理。资源及对象仅来自同一构建目录；支持 Swift Build 的 target 合并 `.o` 和 native 后端的 `target.build/*.o` 布局。
- Quick Look 链接明确设置 macOS 26 最低部署版本，避免链接器采用构建机的 macOS 27。
- 增加主程序内部 `--verify-packaged-render` 入口。在初始化 SwiftUI App、偏好、文档和更新服务之前分流，使用非持久化 WebPage 和临时回执。
- 自检使用主程序实际链接的 HTML 生成、资源定位、就绪判定和正文替换代码，以及包内 CSS/JS。验证字体、20px 间距、正文变更、真实滚动位置和源码锚点。
- 外部验证器保留静态清单检查，通过 `open -n` 启动指定 `.app`，校验随机 nonce、bundle 路径及原子回执。等待以主程序回执为准，不能把 `open` 提前返回当作自检完成。旧主程序没有自检入口时直接拒绝启动。
- 增加 `--output PATH.app`，便于在临时目录验收而不覆盖安装版本。
